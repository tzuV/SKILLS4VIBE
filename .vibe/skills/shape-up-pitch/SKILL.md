# Shape Up Pitch Writer

## Quick Start

User says: "I need to pitch a project" → Ask: "What's the problem?" → Then ask for appetite, solution, rabbit holes, no-gos → Draft pitch with 5 ingredients.

## The 5 Ingredients

Always include in every pitch:

1. **Problem** - Specific story showing why status quo doesn't work. Tests fitness of solutions.
2. **Appetite** - Time box (e.g., "2 weeks small batch"). Constrains the solution.
3. **Solution** - Core elements at high level. Easy to understand immediately.
4. **Rabbit holes** - Details worth calling out to avoid problems.
5. **No-gos** - Functionality intentionally excluded to fit appetite.

## Workflow

### Step 1: Gather Ingredients
Ask user for each ingredient. Push back if any are missing. Unshaped work (problem without solution or vice versa) is not ready to pitch.

### Step 2: Visual Techniques
- Use **fat-marker sketches** for high-level concepts
- Add **embedded sketches** to show placement
- Include **annotated sketches** with call-outs for complex ideas
- Avoid wireframes/high-fidelity mocks (boxes in designers)

### Step 3: Format Pitch
Present as structured document:
```
**Problem:** [specific story]
**Appetite:** [time box]
**Solution:** [core elements]
**Rabbit holes:** [details to avoid issues]
**No-gos:** [explicitly excluded]
```

## Common Pitfalls

- ❌ Starting with solution without problem
- ❌ Problem without solution (unshaped work)
- ❌ Overspecifying design (wireframes, colors)
- ❌ Skipping appetite constraint
- ❌ Not stating no-gos

## Basecamp Style

- Post pitches asynchronously for review
- Comments should poke holes, not vote yes/no
- Yes/no happens at betting table
- Use fat-marker sketches on iPad for clarity

## When To Use

- User says: "write a pitch", "shape this project", "create a bet"
- User describes a problem/solution but hasn't structured it
- Team needs to decide what to build next
